# Title

Test fixtures and deterministic fixture-git helper

## Summary

Create the four fixture repositories of DESIGN §14.1 under
`packages/onboard/test/fixtures/` and a helper that materializes them into temp dirs with
**deterministic git history** (fixed authors/dates → identical commit SHAs on every
machine). Hostile fixture content (XSS filenames, symlinks, fake secrets) is created by
the helper at test time, not committed.

## Context

Analyzer issues (06–16), tour issues (17–22), the secret gate (23), and the gates
(36, 37) all assert against these fixtures. Deterministic SHAs make git-analyzer tests
and the golden bundle stable.

## Scope

All paths below are under `packages/onboard/`:

- `test/fixtures/mini-express-app/` — committed source tree (exactly the 18 files listed below).
- `test/fixtures/js-lib/` — plain JS library, no tsconfig (6 files listed below).
- `test/fixtures/plain-docs/` — markdown-only repo (4 files).
- `test/fixtures/hostile/manifest.ts` — programmatic description of hostile content (the tree is generated, never committed).
- `test/helpers/fixture-git.ts` — `materializeFixture(name): Promise<{ dir, cleanup }>`.
- `test/helpers/expected-shas.ts` — frozen expected HEAD SHA + commit count per fixture.
- `test/helpers/fixture-git.test.ts`.

## Detailed Requirements

1. `mini-express-app` file list (exact):
   `package.json` (name `mini-express-app`, scripts `dev/build/test/lint`, deps incl. `express`, devDeps incl. `vitest`, `engines.node ">=20"`), `pnpm-lock.yaml` (minimal valid), `tsconfig.json`, `README.md` (h1 + one paragraph), `CONTRIBUTING.md`, `.github/workflows/ci.yml` (two jobs), `src/server.ts` (creates express app, mounts routes, calls `app.listen` — the entry point), `src/routes/users.ts`, `src/routes/health.ts`, `src/services/userService.ts`, `src/services/notifier.ts`, `src/db/repo.ts`, `src/db/schema.ts`, `src/util/logger.ts`, `src/util/config.ts`, `src/types.ts`, `test/users.test.ts`, `test/health.test.ts`. Call chain must support §6.10 with **direct, resolvable in-repo calls** (framework callback indirection would defeat the tracer): `src/server.ts` calls exported `registerUserRoutes(app)` from `src/routes/users.ts` at top level; the users handler body calls `userService.createUser(...)`; `createUser` calls `repo.insertUser(...)` in `src/db/repo.ts` — ≥ 4 resolvable hops end to end.
2. `js-lib` (6 files): `package.json` (`main: "index.js"`), `index.js`, `lib/parse.js`, `lib/format.js`, `test/parse.test.js`, `README.md` — exercises the no-tsconfig synthesized-program path (§6.6).
3. `plain-docs` (4 files): `README.md`, `docs/a.md`, `docs/b.md`, `LICENSE` — exercises the degradation matrix (§6.1: architecture-only guarantee).
4. Hostile manifest (generated by helper): file named `<img src=x onerror=alert(1)>.ts`
   containing valid TS; `.env` containing `AWS_KEY=AKIA` + 16 uppercase alphanumerics
   (fake, constructed by concatenation in the manifest so the literal never appears in
   the repo); `notes.txt` containing the same fake AKIA token (this one **is** scanned —
   `.env` is excluded at fs-scan, `notes.txt` proves the emit gate); a symlink
   `escape-link` → `../outside.txt` where the helper first writes `outside.txt` in the
   temp **parent** directory containing the canary string `OUTSIDE-SENTINEL-b7a2`
   (issue 36 asserts this canary never appears in any artifact); `big.bin` of 2 MB
   zeros; `minified.js` (single 6000-char line); `docs/日本語-メモ.md`; `crlf.ts` with
   CRLF endings. On win32 the XSS-filename and symlink entries are skipped (documented
   in helper; hostile determinism claims are POSIX-only).
5. `materializeFixture(name)`: copies the committed tree (or builds hostile from its
   manifest) into a fresh temp dir, then runs scripted commits with fixed identities —
   default author `Fixture Bot <fixture@example.com>`; commits 9 and 11 of
   mini-express-app use the second author `Fixture Bot Two <fixture2@example.com>`
   (gives `contributorCount = 2` on files they touch — privacy tests in issue 08 assert
   neither identity ever appears in outputs) — with `GIT_AUTHOR_DATE`/`GIT_COMMITTER_DATE`
   from a fixed table (commit 1 = `2026-01-05T09:00:00Z`, then +1 day per commit),
   committer identity = author.
6. Commit scripts per fixture live next to the fixture as `commits.ts` with the exact
   contract `export const commits: { message: string; touch: string[] }[]` — for each
   commit the helper appends one deterministic marker line to every `touch` path
   (`// commit <n>` for code, `<!-- commit <n> -->` for markdown, a `# commit <n>` line
   for other text) and commits all of them. mini-express-app distribution (12 commits,
   chosen so §6.4 thresholds are provably met): `src/services/userService.ts` in
   commits 3,5,7,9,11 (5 total — strictly the max; every other file ≤ 4);
   `src/db/repo.ts` in commits 5,7,9,11 (4 total, all shared with userService → pair
   count 4, lift = 4·12/(5·4) = 2.4 > 2.0); remaining commits spread over routes/util/
   tests/docs. js-lib 3 commits; plain-docs 2; hostile 2 (the `.env` and `notes.txt`
   committed — realistic leak).
7. Helper must set `core.autocrlf=false`, `commit.gpgsign=false`, default branch `main`,
   and be independent of user-level git config (`GIT_CONFIG_GLOBAL=/dev/null`,
   `GIT_CONFIG_SYSTEM=/dev/null`, explicit `git -c user.name=… -c user.email=…`).
8. `expected-shas.ts` freezes `{ headSha, commitCount }` per fixture (computed once on
   POSIX, committed); tests assert materialization matches. Changing fixture content
   intentionally means updating these constants in the same PR (acts as a
   tamper-evident seal).

## Acceptance Criteria

- [ ] Every fixture materializes to the frozen `{ headSha, commitCount }` from `expected-shas.ts`, twice in a row (POSIX; assert equality both runs).
- [ ] mini-express-app per-file commit distribution matches the table in requirement 6 (assert counts for `userService.ts` = 5, `repo.ts` = 4, shared = 4).
- [ ] Hostile materialization creates all manifest entries on POSIX (symlink verified with `lstat`; `../outside.txt` contains the canary), and the fake AKIA string appears in `notes.txt` and `.env` only.
- [ ] Committed fixture trees contain no `.git` directories and no real-looking secrets (`git grep -E "AKIA[0-9A-Z]{16}"` over the repo returns nothing — hostile token is built by concatenation).
- [ ] All four fixtures materialize in < 5 s total on CI.

## Validation

`pnpm --filter onboard-cli-placeholder test` (fixtures suite). Reviewer runs
`materializeFixture` locally on macOS and compares HEAD SHA with the CI-logged SHA.
