# Title

Test fixtures and deterministic fixture-git helper

## Summary

Create the four fixture repositories of DESIGN §14.1 under
`packages/onboard/test/fixtures/` and a helper that materializes them into temp dirs with
**deterministic git history** (fixed authors/dates → identical commit SHAs on every
machine). Hostile fixture content (XSS filenames, symlinks, fake secrets) is created by
the helper at test time, not committed.

## Context

Analyzer issues (06–16), tour issues (17–22), the secret gate (23), and the gates
(36, 37) all assert against these fixtures. Deterministic SHAs make git-analyzer tests
and the golden bundle stable.

## Scope

- `test/fixtures/mini-express-app/` — committed source tree (~25 files, see below).
- `test/fixtures/js-lib/` — plain JS library, no tsconfig (~8 files).
- `test/fixtures/plain-docs/` — markdown-only repo (~5 files).
- `test/fixtures/hostile/manifest.ts` — programmatic description of hostile content (the tree is generated, never committed).
- `test/helpers/fixture-git.ts` — `materializeFixture(name): Promise<{ dir, cleanup }>`.
- `test/helpers/fixture-git.test.ts`.

## Detailed Requirements

1. `mini-express-app` file list (exact):
   `package.json` (name `mini-express-app`, scripts `dev/build/test/lint`, deps incl. `express`, devDeps incl. `vitest`, `engines.node ">=20"`), `pnpm-lock.yaml` (minimal valid), `tsconfig.json`, `README.md` (h1 + one paragraph), `CONTRIBUTING.md`, `.github/workflows/ci.yml` (two jobs), `src/server.ts` (creates express app, mounts routes, calls `app.listen` — the entry point), `src/routes/users.ts`, `src/routes/health.ts`, `src/services/userService.ts`, `src/services/notifier.ts`, `src/db/repo.ts`, `src/db/schema.ts`, `src/util/logger.ts`, `src/util/config.ts`, `src/types.ts`, `test/users.test.ts`, `test/health.test.ts`. Call chain must support §6.10: `server.ts → routes/users.ts (handler) → services/userService.ts → db/repo.ts` with ≥ 4 resolvable hops.
2. `js-lib`: `package.json` (`main: "index.js"`), `index.js`, `lib/parse.js`, `lib/format.js`, `test/parse.test.js`, `README.md` — exercises the no-tsconfig synthesized-program path (§6.6).
3. `plain-docs`: `README.md`, `docs/a.md`, `docs/b.md`, `LICENSE` — exercises the degradation matrix (§6.1: architecture-only).
4. Hostile manifest (generated by helper): file named `<img src=x onerror=alert(1)>.ts`
   containing valid TS; `.env` containing `AWS_KEY=AKIA` + 16 uppercase alphanumerics
   (fake, constructed by concatenation in the manifest so the literal never appears in
   the repo); `notes.txt` containing the same fake AKIA token (this one **is** scanned —
   `.env` is excluded at fs-scan, `notes.txt` proves the emit gate); a symlink
   `escape-link` → `../../outside.txt`; `big.bin` of 2 MB zeros; `minified.js` (single
   6000-char line); `docs/日本語-メモ.md`; `crlf.ts` with CRLF endings. On win32 the
   XSS-filename entry is skipped (documented in helper).
5. `materializeFixture(name)`: copies the committed tree (or builds hostile from its
   manifest) into a fresh temp dir, then runs scripted commits with
   `GIT_AUTHOR_NAME=Fixture Bot`, `GIT_AUTHOR_EMAIL=fixture@example.com`,
   `GIT_AUTHOR_DATE`/`GIT_COMMITTER_DATE` from a fixed table (e.g. commit 1 =
   `2026-01-05T09:00:00Z`, then +1 day per commit), committer identity = author. Commit
   scripts per fixture live next to the fixture (`commits.ts`): mini-express-app gets
   **12 commits** shaped so that `src/services/userService.ts` is the top hotspot (≥ 5
   commits) and `userService.ts`+`db/repo.ts` co-change ≥ 4 times; js-lib 3 commits;
   plain-docs 2; hostile 2 (the `.env` and `notes.txt` committed — realistic leak).
6. Helper must set `core.autocrlf=false`, `commit.gpgsign=false`, default branch `main`,
   and be independent of user-level git config (`GIT_CONFIG_GLOBAL=/dev/null`,
   `GIT_CONFIG_SYSTEM=/dev/null`, explicit `git -c user.name=… -c user.email=…`).

## Acceptance Criteria

- [ ] `materializeFixture("mini-express-app")` twice yields the **same HEAD SHA** both times (assert equality) and 12 commits.
- [ ] Hostile materialization creates all manifest entries on POSIX (symlink verified with `lstat`), and the fake AKIA string appears in `notes.txt` and `.env` only.
- [ ] Committed fixture trees contain no `.git` directories and no real-looking secrets (`git grep -E "AKIA[0-9A-Z]{16}"` over the repo returns nothing — hostile token is built by concatenation).
- [ ] All four fixtures materialize in < 5 s total on CI.

## Validation

`pnpm --filter onboard-cli-placeholder test` (fixtures suite). Reviewer runs
`materializeFixture` locally on macOS and compares HEAD SHA with the CI-logged SHA.
